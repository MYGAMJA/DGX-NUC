# 왼다리 CAN 디버그 + id=1/7 보드 교체 계획 (2026-05-21)

> 문제: 왼다리 CAN 통신 안 됨. id=7 단독 테스트 중. id=1/id=7 새 BESC 보드로 교체 예정.

---

## 1. 결론 먼저 (TL;DR)

- **CANable 어댑터·slcand·CAN 송신은 정상**임이 증명됨.
- **id=7은 device_id 0~127 어디로도 응답 없음** — 문제는 물리적으로 id=7 쪽.
- 가장 큰 함정이었던 "가비지 프레임 폭주"는 **stale slcand**였음 (하드웨어 문제 아님).
- id=1·id=7은 새 보드로 교체 예정. **id=7은 캘리브 값 재사용 가능, id=1은 재캘리브 필요.**

---

## 2. 진단 과정에서 밝혀진 것

### 2.1 "가비지 프레임 폭주" = stale slcand (★ 핵심 교훈)
- 증상: candump 하면 랜덤 ID·데이터 쓰레기 프레임이 쏟아짐.
- id=7 CAN 선을 **완전히 분리한 상태에서도** 가비지가 계속됨 → CAN 버스/배선 문제 아님.
- **slcand 재시작 후 candump = 무음(정상).**
- 원인: CANable USB를 뽑았다 끼우면 slcand가 옛 fd를 붙들고 시리얼 동기화가 깨짐 → 가비지.
- **교훈: CANable USB 재연결할 때마다 slcand 재시작 필수.** 안 그러면 sweep 결과 전부 신뢰 불가.
- slcand 수동 재시작 (CANable 1개만 꽂혔을 때):
  ```
  sudo killall slcand; sleep 1
  sudo slcand -o -c -s8 /dev/canable-left can0; sleep 1
  sudo ip link set up can0
  ```

### 2.2 CANable 어댑터 = 정상
- CAN 쪽 아무것도 안 꽂힌 상태에서 slcand 재시작 → candump 무음. 정상 어댑터는 빈 버스에서 무음이어야 맞음.

### 2.3 CAN 송신 = 정상
- candump를 켜둔 채 sweep → 핑 프레임 30개 전부 루프백으로 확인됨 (ID `201`~`21E`, data `CA`).
- can0가 프레임을 정상적으로 내보냄.

### 2.4 id=7 = 응답 0
- 깨끗한 slcand 상태에서 device_id **0~127 전수 sweep → 전부 무응답.** 버스 완전 무음.
- id=7 BESC: 전원 들어옴, LED 점등(아이들). 펌웨어는 살아 있음.
- slcan은 ACK/에러 상태를 커널에 안 올림 (에러 카운터 전부 0 고정) → **소프트웨어 진단은 여기까지가 한계.**

### 2.5 id=7 termON 펌웨어 플래시 완료
- `st-flash --reset write firmware_termON.bin 0x8000000` → written & verified.
- config page(0x0801F800) 안 건드림 → device_id 보존.

## 3. 현재 미해결 — id=7이 통신 안 하는 이유

소프트웨어·어댑터는 깨끗하므로 원인은 물리적으로 id=7 쪽:

1. **(유력) CAN 3선 — 자르고 다시 이은 부위.** id=7은 예전 왼다리에선 통신됐고, 그 뒤 바뀐 건 선 절단·재연결뿐. H/L 뒤바뀜 또는 냉납/헐거움이 "완전 무음"의 흔한 원인.
2. (낮음) id=7 BESC CAN 트랜시버 불량.

→ **어차피 id=7은 새 보드로 교체 예정이므로 이 배선만 새 보드에 깨끗하게 다시 하면 됨.**

확인하려면 (멀티미터 없이): 확실히 되는 모터를 이 케이블에 그대로 물려 sweep — 뜨면 케이블 정상, id=7 문제.

## 4. id=1 / id=7 새 보드 교체 계획

### 4.1 캘리브 값 재사용 가능 여부

| | 저장된 flux_offset | 상태 |
|---|---|---|
| **id=7** (`motor_id7_after_cal.json`) | −53.86, phase_order 1, pole_pairs 14 | ✅ 재사용 가능 |
| **id=1** (`motor_id1_after_cal.json`) | 0.0 (깨짐), pole_pairs 14 | ❌ 새로 캘리브 필요 |

- id=7: −53.86 재사용 가능. (단 readme2 표엔 −47.58로 적혀 불일치 — after_cal.json이 최신이라 −53.86 권장, 첫 구동 시 검증.)
- id=1: 저장본 0.0(캘리브 실패본), readme2의 −63.62도 미검증 → **id=1은 새 보드에서 전기 캘리브 새로.**

### 4.2 flux_offset 재사용 원리 + 조건
- flux_offset은 보드 속성이 아니라 **모터+엔코더 기계적 정렬** 속성. BESC만 바꾸고 모터·AS5600 엔코더·마운팅 안 건드리면 값 유효.
- **결정적 조건: 모터 3상 선을 새 보드에 같은 순서로 연결.** 상 순서 바뀌면 phase_order 틀어지고 flux_offset 무효.

### 4.3 새 보드 셋업 절차
1. **Recoil 펌웨어 플래시** (새 보드는 공장 펌웨어):
   - 조립된 왼다리에서 id=1·id=7은 중간 노드 → **termOFF**.
   - 단독 벤치 테스트로 끝점에 쓸 거면 termON.
2. CAN 접속 → **device_id 설정** (사용자가 직접).
3. 전체 config 기록: 모터 파라미터·게인 + flux_offset/phase_order → `store_settings_to_flash`.
4. **첫 POSITION 명령은 저전류로 조심** — cogging·과전류 시 offset 틀린 것.

> id=7 config를 백업 JSON → 새 보드로 복원하는 스크립트는 작성 가능 (calibrate_one.py read의 반대).
